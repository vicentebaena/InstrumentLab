# Adding an oscilloscope model / Añadir un modelo de osciloscopio

The DS1102E is the complete functional adapter. The DS1104Z Plus supports four channel keys, coupling/probe submenus, inversion, vertical/horizontal scale and position, and edge-trigger source, slope and level controls. Its remaining controls are deferred. New models reuse the existing oscilloscope state, commands and signal renderer. They do not need copies of scale, visibility, selection, position or practice-reset logic.

## Shared layers

- `app/oscilloscope.js`: instrument state transitions and SVG signal rendering. It has no model names or faceplate DOM IDs.
- `app/oscilloscope-controller.js`: actions against the current shared state and experiment. Both the main preview and instrument screens read through this controller.
- `app/instrument-controls.js`: rotary dragging, wheel accumulation, keyboard directions and pointer cancellation. It holds gesture state only.
- `app/oscilloscope-panel.js`: common front-panel wiring and projection of channel visibility, selection, sliders and channel-menu state onto supplied elements.
- `app/instrument-window.js`: opening, closing, dragging, focus and foreground ordering, also used by the generator.
- `app/circuits.js`: each practice's `instrumentDefaults`; AUTO delegates to the application's existing practice restoration.

## Model adapter

Follow `app/ds1102e-panel.js`: supply the photograph, window configuration, actual DOM elements and display geometry to `createOscilloscopePanel`. The model's HTML/CSS define the button locations and menu layout. The common panel receives elements, not a model name or naming convention.

Display options are `idPrefix` (unique per simultaneous screen), `horizontalDivisions`, `cellWidth` in SVG units and `footerScales`. DS1102E uses twelve divisions, 40-unit cells and the lower CH1/CH2/Time row. The main preview uses the selected model’s screen interface; DS1102E retains twelve divisions and the same geometry as its instrument window. Changing an ID prefix cannot change signal geometry.

The common panel supports the present channel/menu keys, AUTO and three rotary controls. A model with another menu layout can provide its own presentation adapter and call `controller.actions.channel`, `menu`, `scale`, `timeScale`, `position` and `auto`; the state transitions remain shared. New menu behaviour should first become an explicit common state/action if it affects signals. Coupling is implemented through the shared selection registry; Probe uses the same registry and confirmation flow; bandwidth remains display-only.

Create one controller for the experiment, then pass it to the desired model adapter. Its `getSettings()` always reads the current state, including after a practice reset; adapters must not keep private copies of electrical settings. Rendering a panel must not bind new listeners or mutate instrument settings. Add the new adapter's script before `main.js`, and connect the chosen instrument's open action when model selection is implemented. No model selector or second production model has been added in this refactor.

## Verification

`tests/oscilloscope-panel.test.cjs` exercises two panels with arbitrary model IDs and different geometries sharing one controller. It checks channel menus, visibility, scale directions, position, rotary/wheel input, AUTO and translation. Existing model and practice-default tests cover circuit physics, signal formatting, independent channels, ground-marker priority and restoration.

Model adapters supply `submenuViews`, keyed by registry name. Each view maps its button, submenu element, main-menu value element, option elements, translation key and value formatter. The common panel handles opening, highlighting, confirmation projection and the shared `selectionKnob` / `submenuIndicator`. There are no Coupling-specific DOM bindings in that layer.

## Reusable rotary submenu selection

`oscilloscope.submenus` registers each submenu’s channel property and allowed options. `openSubmenu`, `stepSubmenu` and `confirmSubmenu` manage the pending selection independently of committed channel state. Menu closure and channel switching discard the pending value. The controller exposes `submenu(name)`, `submenuStep(direction)` and `submenuConfirm()`. The optional `selectionKnob` uses the shared rotary binding with confirmation-on-press; drag-generated clicks are suppressed to prevent accidental confirmation. Clockwise/down/right advances, counterclockwise/up/left goes back, and the wheel works too. Enter/Space confirms. The DS1102E maps the beige multifunction knob to this element.

The Coupling registry stores DC/AC/GND. The renderer applies it per channel, including dense-frequency ranges: DC preserves voltage, AC subtracts the circuit’s full-period mean, GND plots a horizontal line at the movable ground reference. `circuit.mean(parameters, generator)` supplies analytical input/output means for RC; other models can supply their own or use full-period numerical sampling. This ideal mean removal is the requested behaviour, with no physical high-pass transient emulation.

The Probe registry has numeric options 1, 5, 10, 20, 50, 100, 200, 500 and 1000. The renderer multiplies the post-coupling displayed voltage by `channel.probe`, preserving the movable zero reference and the other channel. Dense range rendering follows the same transformation. GND remains zero. The DS1102E uses one common `.ds1102e-submenu` origin for all popup menus; Probe has compact 20px rows so all nine choices fit above the footer at the minimum faceplate size.

The common controller also exposes `horizontalPosition(direction)`. An optional `horizontalPosition` element in the panel map binds this global rotary control. State stores `horizontalPositionDivisions`, default 0, with 0.1-division steps in ±5 divisions, keeping t=0 visible in both displays. Positive values shift both displayed signals right, independent of channel selection/visibility. Reset/AUTO uses the practice defaults. Model adapters position this control without adding another state implementation. Rotary overlays use the original knob photograph without additional radial marks.

An optional `triggerButton` / `triggerMenu` mapping uses the shared `triggerMenu` action. Opening the trigger menu leaves instrument channel settings and signals unchanged, replacing the current channel menu and cancelling any draft submenu. MENU ON/OFF dismisses it; channel selection and practice reset also leave it. The DS1102E supplies its English rows and rising-edge icon. Source, Slope and LEVEL now use shared trigger processing; other trigger rows remain static.

## Shared trigger and acquisition timing

State stores `trigger: { source, level, showLevel }`; the RC practice explicitly defaults to CH1 / 0 V. `triggerSource` is a registry submenu with `target: 'trigger'`, reusing the same draft/confirm machinery as channel menus. A model maps its Source key/menu/value and optional `triggerLevel` rotary element. The model adapter does not calculate crossings or animate signals.

`createSignals` provides consistent post-coupling/probe samples and ranges, used by trigger analysis and drawing. `analyzeTrigger` selects ONE crossing with the programmed slope from the trigger source. Both channels render about that SAME crossing/time window; the other channel is never independently aligned. `circuit.range` and `triggerCrossing` give analytical RC results (including exponential capacitor crossings); bounded numerical fallbacks serve other models. Vertical channel position only moves the level marker/reference, never changes trigger voltage thresholds or phase. Triggering uses the source channel even if its trace is hidden.

The common controller owns one free-running phase and the 3-second LEVEL-indicator timer. `advance(seconds)` changes both traces together only while unlocked. Main schedules 20 fps screen-only refreshes using requestAnimationFrame, avoiding rerendering the circuit and other controls during animation. `needsAnimation` stops scheduling once locked or when no varying trace is visible. LEVEL resets its timer on every adjustment; hiding its indicators preserves the trigger voltage. AUTO and practice reset clear transient timers/phase.

Screen presentation receives the same acquisition reference and phase for every display. The orange time-zero marker moves with global horizontal position and stays within the narrowest screen, while the level line/T marker uses the source channel’s V/div and vertical zero.

`triggerSlope` registers rising/falling with the same target-trigger option mechanism. The DS1102E maps its third blue softkey, submenu entries and main slope SVG through an optional `renderValue` callback; common panel code remains independent of icon geometry. Trigger state defaults to `slope: 'rising'`; `circuit.triggerCrossing(parameters, generator, channel, rawLevel, slope)` and the numeric fallback both honour that direction. Both channels still share the resulting time origin. Free-running motion advances at 16 divisions/s.

The shared free-run controller stores a bounded time offset rather than cycles/s. Each `advance(seconds)` adds `seconds × freeRunDivisionsPerSecond × timePerDivision`, wrapping by the generator period. `oscilloscope.freeRunDivisionsPerSecond` is 16. Both displays consume the identical offset, so their temporal reference stays shared while each screen retains its native cell width. Main passes the full elapsed time between screen updates; it does not truncate delayed frames. Tests cover frequencies, timebases, both screen widths and equivalence of long versus short steps.

RUN/STOP adapters can supply an optional `elements.runStop` button. The common panel binds `actions.runStop` and projects `aria-pressed=true` while stopped; acquisition logic and the immutable ideal-waveform snapshot belong to the shared controller. `acquisitionRunning` defaults to true. Both displays use the same capture origin, while current display settings continue to reproject the stored waveforms. AUTO or `resetTransient()` plus practice restoration discards the capture.

Physical probes are separate experiment state: `getExperiment()` may return `probes: {1: 1, 2: 10}`. Defaults are one. `createSignals(..., settings, probes)` applies the physical divisor independently of each channel's scope `probe` multiplier; `toRaw`, ranges and trigger crossings use the same conversion. The controller snapshots physical attenuation with stopped waveforms. Model adapters never change the physical switch or automatically compensate it.

## Standard complete-screen projection

Every panel exposes `renderScreen(target, { idPrefix })`. The bench calls this method on the active device panel rather than rendering a separate generic scope. Supply `elements.screenRoot` containing the entire LCD (trace container plus channel/trigger menus and submenus). The common panel projects current state, then copies that complete LCD with prefixed DOM/SVG IDs and references. Keep the LCD styling available outside the hardware dialog and define its bench geometry in the adapter stylesheet. Panels without a screenRoot use their existing model display profile as a fallback. DS1102E supplies screenRoot and both locations now use twelve divisions and identical menus/scale layout. Shared controller physics, acquisition snapshot and controls remain unchanged.

`renderScreen(target, { idPrefix, showMenus, showCursors })` supports optional display layers; both flags default to true. The main bench explicitly sets both false. It still uses the model's geometry, scales and shared controller acquisition, including STOP. Cursor suppression is a renderer presentation option and never changes cursor state. The hardware LCD keeps every layer.

## DS1104Z Plus channel panel

`app/ds1104z-plus-panel.js/.css` supplies the window, faceplate, grid, four channel keys and six-row channel menu. The embedded, self-contained asset in `assets/instruments/ds1104z-plus.js` provides the original enhanced photograph with its signals for the bench thumbnail, and a second variant with the LCD painted black for native live screen overlays. Its original/generated reference images remain private.

The screen uses an 800 × 480 viewBox. Figure 1-12 on PDF page 46 of the private DS1000Z user guide informs the geometry: the grid begins at (84, 32), has twelve columns and eight rows of 48 units, and leaves 84 units on the left, 140 on the right and 64 below. The slightly smaller grid reserves space for the four-channel footer at y=438–468. These are presentation coordinates, not acquisition settings. `renderScreen` mirrors this grid and signals on the main page with unique clip IDs; menus are instrument-only.

The footer always shows all four channel numbers, DC/AC/GND symbols and the current formatted voltage scale. Enabled channels use their own colors; disabled readings are grey. Only the visible channel with its menu currently open gets an illuminated slanted frame. The same readings appear on the main preview.

The main model selector sits below the existing Oscilloscope label. `main.js` preserves model choice across practice reset and language changes. Each model uses its own state/controller: `oscilloscope` for DS1102E and `oscilloscopePlus` for the Plus, both created by the shared state factory (`createState(overrides, channelCount)`). Changing models closes the previous window without changing its settings. DS1102E remains the default.

The Plus reuses shared `pressChannel` transitions and signal rendering through `traceLayerOnly`, `plotGeometry`, `channelNumbers` and `channelColors` presentation options. Keys enable/select/open, or disable/close when repeated with that same channel menu open. Defaults are CH1/CH2 visible, CH3/CH4 hidden, CH1 selected, menu closed. The fixed RC wiring remains CH1=input, CH2=capacitor; CH3/CH4 are unconnected and render 0 V at the grid centre (default position 0), never copied capacitor signals. Their screen colors are pink #f06acb and readable deeper blue #588cff. All four physical channel keys illuminate yellow when enabled. Channel scales/grounds remain independent state.

The menu displays Coupling/DC, BW Limit/OFF, Probe/1X, Invert/OFF, Volts/Div/Coarse, Unit/[V] in the right margin, using current channel coupling/probe values. The Coupling and Probe softkeys are active. Coupling opens DC/AC/GND; Probe opens all 16 factors: 0.01X, 0.02X, 0.05X, 0.1X, 0.2X, 0.5X, 1X, 2X, 5X, 10X, 20X, 50X, 100X, 200X, 500X and 1000X. The shared `probePlus` registry targets the same channel property without changing the DS1102E’s nine options. Repeating either key cycles with wrap and applies each new entry immediately, leaving the submenu open. The vertical CH label uses the menu blue for every channel. The Plus multifunction knob uses shared rotation/wheel/keyboard navigation with bounded ends and applies each entry immediately, keeping the submenu open without an inactivity timeout; pressing the knob can dismiss it. Drag-click suppression is preserved. A halo illuminates around the physical circular arrow while either submenu is open, leaving its dark stroke readable. Shared state changes update the trace, channel menu and coupling symbol in the footer; changing channel or reset cancels pending selection. Invert is an immediate ON/OFF toggle through shared `toggleInvert`/`actions.invert`, cancelling a pending submenu. Its channel flag negates the displayed signal about the channel zero, sorts transformed min/max bounds and reverses the raw crossing slope for the trigger. Dense bands also sort their screen bounds. The large vertical SCALE knob calls shared `actions.scale` with `verticalScalesPlus` (1–2–5 steps, 1 mV/div to 10 V/div); the DS1102E retains `verticalScales` and its 10 mV/div minimum. Rotation, wheel and arrow keys affect only the selected visible channel, with bounded endpoints. The horizontal SCALE knob calls shared `actions.timeScale(direction, horizontalScalesPlus)` with 31 bounded 1–2–5 steps from 5 ns/div to 50 s/div, preserving the DS1102E range. It changes the common timebase even when channels are hidden. The screen header adds yellow RIGOL at the upper left and a blue live H time/div reading just after RIGOL, above the grid, in both window and preview. The smaller vertical/horizontal POSITION knobs reuse shared commands, with 0.1-division steps and ±4/±5 limits. Clockwise raises the selected visible channel or moves the common time axis right. The shared renderer includes the orange T arrow above the grid in its trace layer, following horizontal position in both window and preview; its geometry is relative to the plot top. Trigger MENU below LEVEL opens the native Type/Source/Slope/Sweep/Setting menu through shared `actions.triggerMenu`, cancelling channel menus and pending choices. `triggerSourcePlus` targets sources CH1–CH4; unconnected channels produce a zero signal and cannot trigger. `triggerSlopePlus` targets rising/falling/either; either reuses both existing crossing analyses and selects the earliest valid crossing. Source/Slope use the same immediate blue-key and rotary selection. LEVEL calls the shared source-referenced command and three-second timer. The `persistentTriggerMarker` presentation option adds an always-visible orange left-pointing arrow at the right of the plot; line and readout are transient. DS1102E retains its existing transient marker. Type=Edge, Sweep=Auto and Setting remain display-only, as on DS1102E; AC-line triggering is not simulated. Other submenu rows and photographed controls remain inactive. The main animation loop always uses the selected model controller. The Plus renderScreen refreshes its instrument and preview together; grounding the CH1 trigger source loses lock and produces shared free-running drift until a valid trigger returns. Practice reset restores both models via the shared practice factory.


The Plus Cursor button shares enable/reopen/disable transitions but has no activation light. Its six-row native menu fixes Mode to Manual; Select chooses the axis to move (X = vertical lines, Y = horizontal lines). `cursorSourcePlus` offers CH1–CH4 through the common submenu flow. `selectCursorGroup` selects A, B or AB exclusively; it preserves the shared cursor positions and paired clamping. The Plus passes `allowHiddenCursors:true` when moving so a disabled source still permits coordinate measurement, while DS1102E keeps its visible-source guard and independent A/B toggles. Submenu navigation always takes priority over movement.

With `cursorAxes:'both'`, the shared trace renderer draws four lines whenever cursors are enabled: A solid and B dashed on each axis. Opening another menu keeps the lines and all seven upper-left readings: AX, AY, BX, BY, BX-AX, AY-BY, 1/|dX|. `cursorReadings(state, horizontalDivisions)` computes signed coordinates from normalized positions, common horizontal offset/timebase and the source channel's scale/zero reference. Menu A/B readings use the selected movement axis. Both axes default to one third/two thirds. The main preview's `showCursors:false` suppresses lines/readings without changing the instrument state.


The Plus left Vertical measurement menu stays visible independently of right-hand menus, with channel-colored native SVG icons. `voltageMeasurementsPlus` lists eighteen entries in three full groups of six, with the photographed third group replacing the earlier inferred list by the bottom-left up/down keys. Pages are bounded; blank slots on the last page are disabled. Six physical left softkeys register the current selected channel and parameter in independently cloned `oneKey` state. Up to five live readings appear between the grid and channel footer (including the main preview); repeated entries move to the end. The normal Measure menu/state is unchanged and the Plus right Measure menu remains deferred.

The shared voltage statistics supply the added Vupper/Vmid/Vlower values as Vbase + 90/50/10% of Vamp, and population Variance as the mean squared deviation from Vavg. Variance displays squared voltage units. All readings use the visible acquisition interval and shared STOP capture; clipped/hidden/unconnected signals or unresolved flat levels show `*****`. The top-left MENU button alternates Vertical and Horizontal, resetting the group to zero while preserving the five readings. `timeMeasurementsPlus` lists twenty parameters in 6/6/6/2 groups matching the instrument: Period/Freq/Rise Time/Fall Time/+Width/-Width; +Duty/-Duty/+Pulses/-Pulses/+Edges/-Edges; tVmax/tVmin/+Rate/-Rate/DelayRise/DelayFall; PhaseRise/PhaseFall. The newer official DS1000Z guide (2020, printed 6-27 to 6-30) defines counts and rates omitted from the earlier reference. Counts qualify transitions across the 10% and 90% thresholds within the visible acquisition; the ideal model gives matching pulse/edge counts. Rates use the signed 80% voltage change divided by the corresponding transition time, in V/s; instantaneous ideal edges give *****. Delay/phase reuse shared crossing calculations for CH1→CH2. Configurable cross-channel sources await the Measure Settings menu. Three dots in Vertical and four in Horizontal indicate groups with a larger active dot; no numeric page fraction is drawn. Temporal readings reuse shared `timeStatistics`; tVmax/tVmin use sampled extrema timestamps relative to the display temporal-zero marker. Time and voltage readings can coexist.


The second Vertical group uses the supplied Vupper/Vmid/Vlower/Vavg/Vrms/Overshoot icons. The final group follows the supplied instrument photograph: Preshoot/Area/Per.Area/Per.Vrms/AC.Vrms/Period. The user verified that its last button (photographed as “3”) measures Period. It reuses the horizontal period calculation. Variance remains in the shared statistics but is not exposed in this menu. Per.Vrms computes RMS over a complete visible period, including DC; it is unavailable if the window is shorter than a period. AC.Vrms is sqrt(Variance), the visible-window RMS after subtracting its mean. Area is the signed voltage integral over the visible acquisition; Per.Area integrates one complete period, or returns zero if less than a period is visible. Both follow the shared coupling, attenuation, inversion and STOP capture. The steady-state circuit mean gives the exact whole-period area when available; otherwise it uses full-period numerical sampling. Areas display Vs/mVs/uVs/nVs.

## Instrument noise

Practice defaults add independent, zero-mean Gaussian input-referred noise to every scope channel: DS1102E 0.6 mV RMS, DS1104Z Plus 0.5 mV RMS. These are user-selected simulation levels, not manufacturer specifications. Noise is added after physical probe attenuation and input coupling, before display probe compensation/inversion; it remains on grounded and unconnected inputs. Voltage statistics include it; noise-only inputs do not produce periodic time readings. Trigger locking still uses the ideal waveform, without simulated noise-induced trigger jitter. A deterministic Box–Muller source indexed by channel, model, 1 ns time bin and acquisition seed keeps both views and measurements consistent. RUN renews the realization with each display acquisition; STOP holds its seed. This is an educational noise model without analog bandwidth or quantization emulation. Analytical measurement fixtures explicitly disable noise; dedicated tests verify RMS, Gaussian fourth moment, channel independence, probe effects, noise-only measurements, acquisition and reset.

In both models, the first press of a blue submenu key opens the current selection. Repeated presses advance, wrap and immediately apply the selected option without a knob press; the list remains open. This also registers each selected measurement. DS1102E rotary navigation retains bounded draft selection with press/Enter confirmation. The Plus passes applyImmediately for bounded rotary selection without confirmation; its submenus remain open without a timer. The three-second trigger-level timer only hides the level line/readout. Direct toggles retain their existing behavior.

Plus channel Probe changes rescale the stored V/div by new probe factor / old probe factor, preserving the underlying input scale and trace height. The vertical SCALE knob uses the base 1–2–5 sequence multiplied by that channel’s current probe factor, including both endpoints: X1 1 mV/div–10 V/div, X2 2 mV/div–20 V/div. Slider index/readout and both channel footers use this same scale. All 16 factors are supported, including fractional mV labels. Physical probe switching remains independent, and the DS1102E behavior is unchanged.

Plus Cursor opens in Mode OFF, with only the Mode row/key visible and no cursor lines. Its submenu displays OFF/Manual and disabled Track/Auto placeholders. Blue-key cycling and rotary movement select OFF/Manual immediately while preserving the open list. Manual enables the existing six-row menu and four lines; OFF hides the other keys, lines and readings. Reopening after another menu retains Manual and its positions; pressing Cursor while its own menu is open sets OFF and closes it. The physical Cursor hit area is restricted to 3.8% of faceplate width. DS1102E cursor behavior is unchanged.

The Plus physical RUN/STOP key calls the shared runStop action: yellow in RUN, red in STOP. STOP freezes waveform inputs, probe attenuation and noise realization in both views; display controls remain usable. A second press resumes live acquisition; practice reset restores RUN. The other model remains independent.
