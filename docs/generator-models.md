# Adding a generator model / Añadir un modelo de generador

The DG822 adapter supplies its photograph, window, element mapping and English LCD conventions. Reuse the following modules when adding a model:

- `app/generator.js`: parameter metadata, display-unit conversions, validation, waveform-dependent AC RMS conversion, waveform changes preserving the programmed amplitude and independent output toggles. It has no DOM or model names.
- `app/generator-controller.js`: actions against the current shared generator settings: `parameter(name, value, unit)`, `waveform(name)`, `channel(number)` and `output(channel)`. `getChannel(number?)` and `reading(name, channel?)` use the selected channel when omitted. The main circuit summary explicitly reads channel 1.
- `app/generator-panel.js`: numeric editor, unit options, validation feedback, OK/Exit/Escape focus, waveform menu transitions, output key state and reading refresh. It receives actual elements and presentation functions, not model-specific IDs.
- `app/instrument-window.js`: the existing shared movable instrument window.

Follow `app/dg822-panel.js`: pass a controller, element map and presentation profile to `createGeneratorPanel`. The profile defines reading text, accessibility labels, editor title/value formatting, phase text, RMS explanation, preview SVG path and waveform text and channel/output labels. The DG822 keeps its grouped fractional digits, fixed phase and untranslated English screen here; another model can choose its own display format and labels. Its HTML/CSS define the carátula and menu layout. Both active waveform choices remain Sine and Square; the other six DG822 tiles remain disabled.

A different menu/editor arrangement can call the same controller actions from a custom adapter. Keep unit conversion and electrical effects in the shared generator module. Never store an adapter's element ID in parameter metadata or retain a private copy of experiment settings. The shared generator state stores `selectedChannel` (default 1), CH1 parameters at the root and independent CH2 parameters/units in `channel2`. State factories clone the nested CH2 object. The footer receives `channelButtons` and `channelWaves` maps for channels 1 and 2; each zone displays its waveform and fixed HighZ load, highlights the selected channel and selects the settings edited by the keypad and waveform menu. Selection does not toggle outputs. A waveform preview is presentation; RC voltages continue to come from the circuit model, with only CH1 connected and CH2 independent/disconnected in the RC practice.

Practice defaults and AUTO restoration remain in the existing practice lifecycle. After replacing experiment settings, reset the panel menu and render; controllers read the new state through their callbacks. Closing/reopening preserves generator settings and returns the DG822 to its parameter screen. The numeric editor fills the LCD with a touchscreen keypad (digits, decimal point, sign, backspace, Exit and OK), an editable value and all parameter-specific unit choices. Keyboard entry and Enter/Escape are supported. Edits stay pending until OK/Enter; Exit/Escape, Menu and practice reset discard them. Validation appears inside the LCD. Pass `editor.container`, `input`, `units`, `title`, `note`, `form`, `cancel`, `error` and `keys` to the shared panel; keypad keys declare `data-edit-key`. The editor and waveform menu keep their English text. No second production model or model selector is added by this refactor.

`tests/generator-panel.test.cjs` exercises two panels with one controller and different reading/editor presentations, including channel selection/independent settings, units, RMS, menu transitions, invalid/cancelled edits, focus, outputs, reset and repeated rendering. `tests/dg822.test.cjs` checks the original conversions, numeric format and RC effects. `tests/practice-defaults.test.cjs` checks restoration for different active practices.

## Resumen en español

Cada modelo aporta su carátula, los elementos de control y las convenciones de pantalla. Las unidades, conversiones RMS, validación, selección de onda, salidas y edición común se reutilizan. El DG822 conserva sus formatos y su pantalla en inglés. Otro modelo puede organizar sus menús de otra manera y llamar a las mismas acciones sin duplicar su funcionamiento.
